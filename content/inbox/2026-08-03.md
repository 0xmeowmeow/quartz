Never images. Pixel graphics, ASCII, ANSI. Never compressed formats (MP3, video, etc). Only generative.

Never traditional interfaces. Avoid windows, lists.

Always simple to navigate from keyboard. Low key strokes. Obvious options and ways to move using graphical elements such as maps, nodes, circuits, layouts with single keystrokes.

Powerful for analysing data.

Ability to shift dimensionally up and down as a given.

As much power given to performance as possible with zero bloat (except for aesthetics, where it gives a disproportionate amount (eg rendering fractals in 3d in pixels or ascii, interactive elements like OS "screens" flipping on faces of a cube)

Information focused, data secondary.

It should not have to explain itself. A user should be able to navigate the first time they use it. They should also be able to add to it the first time they use it. They should not be able to break it in such a way they can't unbreak it (e.g they should be able to grab a program from a list and add it to a menu, but if they delete it from the menu, it's always in the list)

It should be simple to program. A user should be able to come in with an idea for say, a way to interogate DNA and a local AI should be able to help them create the module, but let the user do the work.

There should be a way to edit modules inside the TUI, live.

It should not be restricted to retro options. Most of the TUIs are trying to recreate the past. We will use the ease of use of things like mainframes (single letter navigation, modular, even screens that are generated dynamically for a specific use) with the power of modern computers. We can render/shade in ASCII, but we can use the GPU to do it. It should feel like computers of the 80s (mainframes and amigas, not DOS).

It should allow for creating peripherals over ESP32 to be super easy.

Where possible, it should show the systems. I am a systems thinker and i like graphical representations over lists.

Linux functions are complex to learn. I still struggle to do basic things because I am not a coder. I should be able to hit a key to bring up a pseudo-console and instead of typing 'man' i could type "scb mv" like simple command builder and it would give me options to pick from and navigate those using tab and arrows. It would help me do things like move files or things that are painful in CLI.

It should be able to pull in things from all over the internet that are open source.

It is not for coders. It is for people that are sick of GUI and love art and science. It should make their life easier.

It will follow a concrete system. The simplicity comes from understanding the system. That's the way Linux is meant to be, but why can't I understand it?

It should never hide things. It should always allow for exploration (e.g ecwatch app we built was revelatory)

Information caan be communicated using graphical elements such as bars, readouts in waves, colour, HEAT MAPS, any way that the user can instantly understand without it being numbers and text. Think about like the way that github shows activity, but for everything in the way that's *best* for that thing.

Nothing is decorative. Every widget needs to be able to be focused and interacted with. It should be able to be piped into other things too. Every element of the interface is a node and it's own graph.

A user shuld be able to download a custom skin that radically changes the way it interacts, but underneath, it's just nodes and edges. The options for how to get from A to B might be a walk along a graph, but the user might just hit "m, t, w" which would go MAKE -> TDF -> WRITE and each letter would open a new menu, or move the face of the cube, or open a complete new interfae with it's own way of displaying stuff, or navigate, but it all has to be intuitive to the point of literally never being able to fuck up this way "what you want to do happens with no ambiguity. Failing that, it should be easy to move back a step and then try again." Not endless fucking man pages where i try a bunch of things and they never work constructing complex commands that don't always do what i expect and not knowing the syntax, having way too much noise and not enough signal.

The system needs to be completely interoperable. Each module should be able to be exported to use anywhere else, and we should be able to pull in anything in any language where possible. We should be able to do this by reducing the code on github in any language to work out "what does it do, how does it do it, how do the elements interact" as a grpah and then rebuild it inside this thing.

People should be able to build the thing collaboratively. There should be internal forums, chat, RSS, git for code, modules, graphical elements, papers, etc.

It should feel like the internet pre-2010.

It should be able to connect with the fediverse.

It allows for commerce but only at the individual person-person level.

People should be able to do things like create a logo for google in ASCII and other people that browse to that page should be able to see different options for rendering the page.

Maths should be able to be rendered beautifully with a focus on graphical representations. Notiation should be able to be configured differently, focusing less on formulae and more on relatioships and visualisation.

Navigation should be by interest. I remember in 1998 being able to find every other rollerblader in the world through web rings and 'links' pages. I want that back.

Music should be midi, with people being able to make that sound however they want.

There should be animations that can render in vectors, but shaders or something should force a certain aesthetic.

Additionally:
- privacy focused
- cyberddeck focused
- anonymous
- anti-regulation and tracking in all possible ways
- very liberatarian and free (freedom to do what you want, early internet vibes)
- pgp identities, blockchain as foundational to most things, distributed
- community focused and zero friction to join and create in a new community
- support for ALL unicode. Text is more than just a keyboard. This whole ecosystem is glyph based, and users should be able to expand it without requiring unicode to recognise it.
- creating programs and proc gen art and scripts to do things like interrogate genomes should be super simple. Things like functions should not have to be memorised - they should be little modules with parameters and you can go down a dimension and edit *that* thing, and when you do it becomes a new module that requires certain info (what it does) and then that propagates. There is no private code. The entire ecosystem is forced open source and free.
- each identity requires a pgp key. The entire thing runs on that. You can have as many as you want, but always at least one. Reputation is built through interaction, and that is tied to an identity.
- Not creepy. Like no surveillance, no "people you may know" bullshit.
- universal keybindings to vim or something. like maybe you just have to learn a few things that are displayed on screen (like a toggleable cheat sheet) and a certain key stroke always brings this up in every program. You should be able to write your own custom keybindings, but the core functions need to be universal. We might have new things like, pull and push as well as copy and paste, and other things like this.
